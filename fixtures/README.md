# Fixtures

Everything here is **fictional** and exists for offline, deterministic tests and the demo.

| Path | What it is |
| --- | --- |
| `habr/` | Hand-written HTML that approximates Habr's public markup (author list, article pages, a weekly top list, a malformed page, an article without metrics). Generated by `habr/generate.py`. Not captured from habr.com. |
| `habr/manifest.json` | URL → fixture file map. The demo seeds the HTTP cache with it, so the real Habr adapter runs without network access. |
| `platform/` | Three weekly Habr-like datasets in the `storyops research import` format (metadata, metrics and abstract features only; no article text). Generated by `platform/generate.py`. The share of generic AI titles rises week over week. |
| `author/` | A Telegram post in Markdown with frontmatter, imported with `storyops author import` (the author's archive). |
| `projects/notegarden/history.json` | A scripted git history (fixed dates) replayed into a real git repository by `src/demo/fixture-repo.ts`. Generated by `generate.py`. |
| `review/article.md` | A fictional **human-written** article used to demonstrate and test the read-only review. It deliberately contains an unsupported performance claim, a duplicated paragraph and an awkward (bureaucratic) phrase. StoryOps never generated it and never modifies it. |
| `review/author-input.md` | The fictional author's own notes for that article (MUST USE / DO NOT USE). |

The fixture scenario: two Habr articles introduced the project and its first
("one-off audit") architecture; afterwards the repository gained a persistent
health model, a finding lifecycle, knowledge analysis and a SQLite store, and
removed the one-off audit. A Telegram post mentioned the lifecycle briefly.
In 2026 the repository added reconciliation receipts (with an ADR, tests and a
bug fix) that the author has not written about.
